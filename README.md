# Spine Draft Kit

Генерує чернетки Spine 4.1.24 для слот-ігор: символи, барабани, рамки, фон, логотип, попапи. Чернетки мають фінальні назви, тому гра працює з ними одразу. Аніматор потім доробляє їх у Spine Editor і віддає файли з тими самими назвами.

## Що потрібно

- [Node.js](https://nodejs.org) 18 або новіший (перевірка: `node -v`). Більше нічого: кит не має залежностей, `npm install` не потрібен.
- Браузер Chrome, Safari, Firefox або Edge. Для превʼю й експорту потрібен інтернет: рантайм Spine і JSZip завантажуються з CDN.
- Spine Editor 4.1.24, щоб доробляти чернетки.

## Запуск

У папці кита:

```bash
npm run dev
```

Відкрий http://localhost:5180. Зупинити сервер: `Ctrl+C`. Інший порт: `PORT=5190 npm run dev`.

Файл `Spine-Draft-Kit.html` відкривається і без сервера, подвійним кліком. Але тоді проекти зберігаються тільки в браузері, а Connect не працює.

## Як працювати

1. **+ Новий** у сайдбарі: назва гри, сітка (барабани × ряди), розмір клітинки, кількість символів, компоненти.
2. У картках компонентів додай картинки. Назва PNG стає назвою символу: `high_1.png` → `animation_symbol_high_1`. Для кожної анімації задай тривалість і рух.
3. Справа «Сітка» показує барабани так, як їх покаже гра. **▶ Спін** запускає справжній спін. «Превʼю» відтворює кожен спайн.
4. **Експорт драфту** збирає zip. Інструкція для аніматора лежить у ньому, у `README.txt`.

Кнопка **i** біля кожного поля пояснює, що воно означає.

## Свої компоненти

Колектор, лічильник, персонаж чи панель на кшталт Lucky 5 збираються з картки «Свій» (або «Персонаж»):

- **Частини**: окремі картинки всередині компонента. Кожна стає кісткою і слотом з тією ж назвою, має батька, центр, розмір, опорну точку, шар (над або під основною картинкою), змішування і прозорість на старті. Без картинки кіт малює заглушку: коло, кільце, світіння, зірку чи прямокутник.
- **Ключі**: кнопка з ромбом у рядку анімації. Кадри для `art`, частин, спейсерів, частин прогрес-бару або `all` лягають поверх руху з колонки «Рух».
- **Експорт** у картці зберігає компонент з частинами, ключами й картинками в `<спайн>.component.json`. **+ → Імпорт з файлу** додає його в будь-який проект, **Імпорт** у сайдбарі теж розпізнає такий файл.

Claude робить те саме через MCP: `add_component` і `update_component` з `parts` і `keys`, `export_component` (за замовчуванням у `projects/components/`) та `import_component`.

## Фінал від аніматора

Аніматор бере драфт у Spine Editor (Import Data), доробляє анімації, спейсери й події і експортує під тими самими назвами: `<спайн>.json`, `<спайн>.atlas` і всі сторінки `.png`. **Імпорт** у шапці картки компонента відкриває вікно, куди кидають ці файли (можна папку або `.zip`; для символів і барабанів кит розкладе файли по спайнах за назвами).

Кит звіряє експорт із драфтом так само, як гра і валідатор арт-репо, і показує різницю: анімації й тривалості, події, спейсери та їхні позиції, скіни, розмір, картинки, сторінки атласу.

- **Помилки** блокують імпорт: інша версія Spine, Nonessential data, бракує анімації, скіна, спейсера чи події з драфту, сторінки атласу, регіону, рантайм Spine не читає файл.
- **Попередження** — фінал відрізняється від драфту (нова чи переставлена анімація, тривалість понад ±10 %, зсунутий спейсер чи подія, цикл зі швом, інший розмір чи root). Імпорт можливий, але кожне попередження треба відмітити окремо: прийняті зберігаються разом із фіналом. Якщо рантайм Spine не завантажився, це теж попередження: тоді не перевірено, чи гра прочитає файл, спейсери, розмір і шви.

Перейменування компонента чи символу переносить його фінал під нову назву; видалений символ забирає й свій фінал.

Після імпорту превʼю, zip і запис в арт-репо беруть файли аніматора (сторінки атласу кит перейменує під спайн), а налаштування компонента лишаються домовленістю: якщо їх змінити, картка покаже, що фінал більше не відповідає драфту. «Повернути драфт» прибирає фінал. Якщо в арт-репо вже лежить фінал, якого немає в киті, запис в арт-репо попередить, що драфт його перетре, і запропонує імпортувати його звідти.

Claude робить те саме через MCP: `import_final` спершу лише перевіряє (`apply: false`), а імпортує тільки з `accept` — попередженнями, які людина підтвердила сама; `remove_final` повертає драфт, `preview` з `draft: true` показує драфт для порівняння.

## Пісочниця і бібліотека

Вкладка **Пісочниця** — ваш особистий верстак (той самий у всіх проектах, інші його не бачать), щоб пробувати й робити компоненти з анімаціями окремо від «Чернеток» і експорту: велике превʼю з паузою, повзунками часу й швидкості, зумом, петлею й кістками, поруч ті самі налаштування, що в картці свого компонента. Готове йде в **бібліотеку** (на командному сервері вона спільна для всіх, локально живе в браузері) або кнопкою «Додати в проект» у «Чернетки» будь-якого проекту. Claude працює там наживо через MCP (`sandbox_*`, `library_*`) і має свої правила, щоб виходило гарно з 2–3 спроб. Докладно: [docs/sandbox.md](docs/sandbox.md).

## Збереження проектів

Проекти автоматично зберігаються в двох місцях:

- у браузері (IndexedDB);
- у папці `projects/<назва>--<id>/`: `project.json` і картинки в `images/`. Це працює тільки через `npm run dev`.

Видалений проект переноситься в `projects/.trash/`. Якщо дані браузера зникнуть, кит відновить проекти з `projects/` під час запуску. Інша папка: `SPINE_KIT_DATA=/шлях npm run dev`.

Передати проект іншій людині: **Експорт** у сайдбарі створює один `.json` з картинками, а **Імпорт** його відкриває.

## Claude (MCP)

Claude Code може сам заповнити кит: просканувати папку з артом, створити проект або заповнити існуючий, додати символи й рамки, зібрати свій компонент з частинами й анімаціями та перенести його в інший проект, імпортувати лейаути гри, розставити компоненти на кістках і посунути кістки, зробити скріншоти (і лейаутів на різних екранах), запустити спін і зібрати zip. Усе відбувається наживо на відкритій сторінці.

1. Один раз додай сервер (шлях до своєї папки кита):

   ```bash
   claude mcp add --scope user spine-draft-kit -- node "/шлях/до/spine-draft-kit/mcp.mjs"
   ```

   Готову команду з правильним шляхом показує кнопка **Connect** у киті.
2. Запусти `npm run dev`, відкрий кит і натисни **Connect**. Колір крапки: жовта — кит чекає Claude, зелена — Claude підключений, синя — Claude працює.
3. У новій сесії Claude Code напиши, наприклад: «Заповни кит артом з `/Users/me/art/my-slot`». Claude спитає, заповнювати існуючий проект чи створити новий. Якщо кит не запущений, Claude запустить його сам.

Сервер кита приймає запити тільки з цього компʼютера. Прибрати MCP: `claude mcp remove spine-draft-kit -s user`.

## Командний сервер

Кит можна поставити на сервер компанії: тоді вся команда працює в тих самих проектах, а Claude Code підключається до нього по мережі. Як розгорнути — `docs/deploy.md`.

**Вхід.** Відкрий адресу кита (наприклад `https://spine-kit.<домен>`) і увійди корпоративним акаунтом. Вийти можна в меню акаунта справа вгорі.

**Спільна робота.** Проекти, картинки й історія зберігаються на сервері. Правки інших людей і Claude видно за секунду, а у шапці видно, хто зараз у проекті. Посилання `/p/<id>` відкриває проект, ним можна поділитися.

**Історія.** Жовта кнопка показує, хто, коли й що змінив (людина чи «Claude · <імʼя>»). Клік по запису відкриває проект у тому стані, новіші записи тьмяніють; «Відновити до цієї зміни» робить його поточним, а якщо просто почати правити, кит спершу попередить, що новіші зміни перезапишуться (в історії вони залишаться). Клік по верхньому запису повертає до поточного стану. ⌘Z скасовує лише твої зміни, а поки відкрита стара версія, ходить по записах.

**Claude Code.** Кнопка **Connect** показує команду, наприклад:

```bash
claude mcp add --transport http spine-kit https://spine-kit.<домен>/mcp
```

Далі в Claude Code: `/mcp` → `spine-kit` → **Authenticate**, і вхід тим самим акаунтом. Якщо OAuth не підходить, у Connect є «Персональний токен» (діє 90 днів, показується один раз). Там же список підключених клієнтів із кнопкою «Відключити».

**Чим відрізняється від локального режиму:**

- кит працює й без відкритої вкладки: Claude має свою вкладку на сервері;
- сервер не бачить твого диска, тому Claude сам заливає арт через `upload_files` і `curl`, а zip експорту скачує за посиланням;
- `open_kit` і `scan_art` недоступні; є `get_history`, `restore_version`, `save_version`;
- зберігається автоматично, кнопки «Зберегти» немає;
- локальні проекти переносяться так: «Експорт» у локальному киті, «Імпорт» на сервері.

Локальний режим (`npm run dev`, Connect, `mcp.mjs`) працює як раніше.

## Для розробки кита

- `src/`: `core.js` (генератори, атлас, перевірка), `ui.js` (інтерфейс), `link.js` (Connect і копії на диск), `spin.js`, `store.js`, `info.js`, `page.html`.
- `npm run dev` стежить за `src/`, перезбирає і перезавантажує сторінку. `npm run build` збирає `dist/spine-draft-kit.html` і `Spine-Draft-Kit.html`.
- `server/bridge.mjs`: API проектів і міст до сторінки. `mcp.mjs`: MCP-сервер (stdio).
- `check/` містить шляхи до конкретного компʼютера і для передачі кита не потрібна.
